# PRI System Rack 開発メモ

開発者向けの資料です。作りの詳細、確かめた結果、過去の不具合とその原因、確認用のツールをまとめています。
使い方は [README.ja.md](../README.ja.md)、APO の仕組みは [WindowsAPO.ja.md](WindowsAPO.ja.md) を見てください。

日付の入った「確かめたこと」は、そのときの開発環境（Windows 10 22H2）での結果です。

## 仕組み

```
各アプリの音 → Windows のオーディオエンジン（audiodg.exe）→ サウンドデバイス
                        │
                  PRISystemRack APO ⇄ 共有メモリ ⇄ 本体アプリ（VST3 を直列に処理、画面表示）
```

- APO はミックス後（GFX）の枠に入り、音を本体アプリに渡して処理結果を戻すだけにする。
- プラグインは本体アプリ（ユーザーのデスクトップ上のプロセス）で動くので、プラグインの画面がリアルタイムに動く。
- 仮想オーディオデバイスも ASIO も使わない。

## ビルド

Visual Studio 2026、Windows SDK 10.0.26100 以降、CMake 3.25 以降、JUCE 8.0.16（`external/JUCE` に置く。JUCE は AGPLv3 / 商用のデュアルライセンス）。

```powershell
git clone --depth 1 --branch 8.0.16-security https://github.com/juce-framework/JUCE.git external/JUCE
cmake -S . -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config RelWithDebInfo
```

JUCE には、CMake の構成のときに次の修正を自動で当てる（`CMakeLists.txt`。当てた印のコメントがあれば何もしない。JUCE を更新して当てる場所が見つからなければ、構成のエラーで止まる）。

- `juce_VST3PluginFormatImpl.h` の `updateMidiMappings`: プラグインに MIDI の CC の割り当てを問い合わせない（`PRI_JUCE_QUERY_MIDI_MAPPINGS=0`。1 にすれば JUCE のもとの動き）。JUCE はプラグインを作ると、16 チャンネル × 130 番の 2,080 回を問い合わせる（`StoredMidiMapping::storeMappings`。MIDI を受けないエフェクトにも）。Waves の古い WaveShell（9.92 / 10.0）のプラグインは、問い合わせのたびに処理部（`WP_InitAlgToHardware`）と画面（`WP_InitGUI`）を作り直して描画資源を残し、GDI オブジェクトを上限の 10,000 個まで使い切っていた。MIDI の入力を持つ GTR Stomp 6 は、問い合わせのたびに工場出荷のプリセットを読み直してメニューを作り（`LoadFactoryPresetToPluginByName` → `AddMenuItem`）、USER オブジェクトを使い続けた（2026-11-15、補助プログラムの `--probe ... stack` で取った呼び出し経路で確認。Cubase では起きない）。割り当ては、プラグインに送る MIDI の CC をパラメーターの変更に読み替えるときだけ使う（`MidiEventList::hostToPluginEventList`）が、このアプリはプラグインに MIDI を送らない（渡す `MidiBuffer` はいつも空）ので要らない。直したあと、L316 Stereo / Mono・L3 MultiMaximizer・C6・GTR Stomp 2 / 6（9.92）・Vocal Rider Stereo（10.0）は、どれも GDI 18 個・2 秒以内で安全チェックを通った（直す前は L316 が 40 秒で GDI 10,000 個、GTR Stomp 6 は 130 秒たっても作り終わらなかった）。最初は「MIDI の入力がないプラグインにだけ問い合わせない」にしたが、GTR Stomp が残ったので問い合わせ自体をやめた（以前の修正が当たっていれば置き換える）。

配布用のビルドでは `-DPRI_ENABLE_LTO=ON` を付けて構成し直す（開発中は LTO を切っておく）。

## インストーラー

```powershell
# dist\PRISystemRack-Setup-<版>.exe を作る（管理者は要らない。build-dist に LTO 有効の Release でビルドしてから Inno Setup でまとめる）
.\Tools\Scripts\build-installer.ps1
# ビルドを省いて、build-dist の今の成果物からインストーラーだけ作り直す
.\Tools\Scripts\build-installer.ps1 -SkipBuild
```

- Inno Setup 6 が要る（`winget install JRSoftware.InnoSetup`。ユーザー単位で入れてよい）。スクリプトは `Installer/PRISystemRack.iss`。版は `CMakeLists.txt` の `project(... VERSION)`（今は 1.0.0）。JUCE が作る exe のバージョン情報のリソース（`<ビルドフォルダー>\PRISystemRack_artefacts\JuceLibraryCode\PRISystemRack_resources.rc`）は版を変えても作り直されないので、`build-installer.ps1` はビルドの前に消す（開発用の `build` では、版を変えたら手で消す）。言語は英語と日本語で、選ぶ画面は出さずに Windows の表示言語に合わせる（`ShowLanguageDialog=auto`）。インストーラーの言語を `HKLM\SOFTWARE\PRISystemRack` の `InstallLanguage`（`en` / `ja`）に書き、アプリはまだ言語を選んだことがない（設定に `language` がない）ときだけ、それを最初の言語にして設定に保存する（すでに設定がある PC では何も変わらない）。
- 入れる場所は `C:\Program Files\PRISystemRack`（変えられない。開発用スクリプトが APO を入れる場所と同じ）。本体・Scanner・Setup・APO の DLL と、落ちたときの記録用の PDB を入れる。スタートメニューにショートカット（デスクトップは選んだときだけ）。
- インストールの流れ: 動いている本体を終了させる（`PRISystemRackSetup.exe quit-app "{app}\PRISystemRack.exe"`。インストール先の本体を `--quit` 付きで起動して頼み（同じアプリのどの exe から送っても、動いている本体に届く）、本体と Scanner が終わるのを待つ。Setup は管理者として動くので、動いているプロセスの exe（どこに置かれたものか分からない）は起動しない。インストール先にまだ本体がない初めてのインストールで、ほかの場所の本体が動いていれば、利用者に終了してもらう。止めてよい Scanner もインストール先のものだけ）→ ファイルをコピー → `register`（ログフォルダーを作って LOCAL SERVICE に書き込みを許可、`DisableProtectedAudioDG=1`、APO の `DllRegisterServer`）。APO の DLL は中身（SHA-256）が変わったときだけ置き換え、すでに入っていた DLL を置き換えるときだけ、その直前に Windows Audio を止めて（`stop-audio`）、登録のあとで動かす（`start-audio`。途中で失敗・取りやめても最後に動かす）。初めて入れるときと、本体だけ変わった更新では音は止まらない。
- 再生デバイスへの付け外しはしない（アプリでデバイスを選んで［有効］を押す）。更新では、今まで［有効］だったデバイスはそのまま。
- Windows Audio を止めるとき（`stop-audio`、［有効］・［無効］の再起動）は、Audiosrv に依存して動いているサービス（機器のメーカーの音声サービスなど）を先に止める（動いていると Audiosrv を止められない）。止めたサービスの名前は `HKLM\SOFTWARE\PRISystemRack` の `StoppedServices` に控え（`stop-audio` と `start-audio` は別のプロセスのため）、動かすときはそれだけを動かし直して控えを消す（もともと止まっていたものは動かさない。控えのためだけに作ったキーが空になれば、キーも消す）。インストーラーが途中で失敗・取りやめになったときも、Setup があれば `start-audio` で戻す（なければ `sc start Audiosrv`）。Audiosrv が止まっても audiodg.exe が 15 秒で終わらなければ、APO の DLL を使ったままなので失敗にする。
- アンインストール: 始める前に本体を終了させ（`quit-app`。終わらなければ、ほかの Windows ユーザーが動かしているかもしれないと知らせて、続けるかを聞く。既定は「いいえ」）、`uninstall`（控えのあるすべてのデバイスを元に戻す（Equalizer APO などの登録を書き戻す。デバイスの登録そのものがもうないものは、書き戻す先がないので控えを消して先に進む。「ない」と分かったときだけで、権限などで開けなかったときは失敗にして控えを残す）→ APO の `DllUnregisterServer` → `HKLM\SOFTWARE\PRISystemRack` を消す（戻せなかったデバイスがあれば控えを残す）→ Windows Audio を再起動して DLL を手放させる）を行ってからファイルを消す。Windows の起動時の登録は、インストール先の exe を指していれば消す。最後に、設定・プリセット・ログ（`%APPDATA%\PRISystemRack` と `%ProgramData%\PRISystemRack`）も消すかを聞く（既定は残す）。`DisableProtectedAudioDG` は、ほかの署名のない APO が頼っていることがあるので戻さない。
- 本体の `--quit` は、動いている本体がなければ何もせずに終わる（インストーラーやビルドの前に、動いているか分からないまま送るため）。

## 開発用のインストール

管理者の PowerShell で実行する。音声サービスを再起動するので、数秒間 Windows の音が止まる（ASIO は影響を受けない）。

```powershell
# APO を CABLE Input に入れる（DLL を更新するときも同じコマンド）。-TestGainDb は確認用のゲイン
.\Tools\Scripts\dev-install.ps1 -Endpoint 'CABLE Input' -TestGainDb 0

# 外して元の状態に戻す
.\Tools\Scripts\dev-uninstall.ps1

# APO だけの確認（入れる → -6 dB を測る → 外す → 元に戻ったか測る）を一度に行う
.\Tools\Scripts\verify-step1.ps1 -Transcript .\build\verify-step1.log
```

- 別の APO（Equalizer APO など）が入っているデバイスには入れない。
- 開発用のスクリプトは `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Audio\DisableProtectedAudioDG=1`（署名のない APO を読み込ませる設定）を書かない。Equalizer APO などがすでに設定している PC でなければ、先にインストーラーで入れるか、手で設定する（インストーラーの `register` は設定する）。

## ログ

- ログ（`%ProgramData%\PRISystemRack\Logs`。ヘルプメニューの「ログフォルダー」で開く）は、どれも 1 MB を超えたら `*.old.log` に回して新しく書き始める（ファイルは 2 つまで。前の `*.old.log` は消える）。`apo.log` は、開いたファイルそのものの名前を変えて回す（`SetFileInformationByHandle` の `FileRenameInfo`）。audiodg.exe と登録中の Setup など、2 つのプロセスが同時に回そうとしても、先に回されて新しく作られた `apo.log` を `apo.old.log` に上書きしない。
  - `apo.log`（APO）: 作成・形式の確認・処理の開始と終了（周期の数・時間切れ・本体がいなかった回数）。対応していないインターフェイスの問い合わせは、同じものはプロセスごとに 1 回だけ書く（Windows は再生中も数秒おきに `{24BDC606-D710-4D62-BE35-BE665FBC3E00}`（SDK にない GUID）などを問い合わせ続け、2026-11-13 には 8.5 MB のうち 9 割がこの行だった）。
  - `setup.log`（`PRISystemRackSetup.exe`）: 再生デバイスへの付け外しと、控え・書き戻した登録。
    - Setup は管理者として動くので、一般ユーザーも作れる `C:\ProgramData` の下のフォルダーをそのまま信用しない（`SecureFolder`）。`PRISystemRack` と `Logs` は、リンク（ジャンクションなど）ならリンクそのものを消して作り直し、持ち主を Administrators にして明示の権限を置き換える（`Logs` には LOCAL SERVICE の変更だけを明示で付け、ほかは親から継承。先に作った一般ユーザーの権限は消える）。`setup.log` は、リンク（シンボリックリンク・ハードリンク）なら名前だけを消して作り直してから追記する（UTF-8）。先に作られたリンクをたどって、管理者として別の場所に書いたり権限を付けたりしないため。
  - `app.log`（本体。`AppLog`）: ProgramData の下のファイルは作った Windows ユーザーしか書けないので、`app` → `app-<ユーザー名>` → `app-<ユーザー名>-2` の順に、書けて、上限を超えたときに `*.old.log` に回せる名前を使う（ほかのユーザーの `app.log` や `.old.log` には書けない・回せないので、回せないまま上限なく大きくならないよう次の名前に移る。前に書けた名前に書けなくなったら、候補を初めから試し直す。ログフォルダーの権限は広げない。管理者として動く Setup も書くフォルダーなので、一般ユーザーが中のファイルを置き換えられないようにしておく）。状態が変わったときだけ書く。起動（前回が正しく終わらなかったか、セーフモードにしたか）・終了、ステータスバーの状態の種類が変わったとき（APO とのつながり、デバイスがない、無効、バイパスなど。処理中の数値の変化では書かない）、［有効］・［無効］の結果（Setup の終了コード）、処理が間に合っていない状態の始まりと終わり、プラグインの読み込みの失敗と 1 秒以上かかった読み込み、エラーで止めたプラグイン（処理・準備・画面）、アプリ用ラックの取り込みの開始・失敗（同じ失敗は繰り返し書かない）・終了と Windows Audio の再起動による作り直し。

## APO だけで確かめたこと（2026-11-03、Windows 10 22H2、VB-CABLE）

音をそのまま通す APO（確認用にゲインだけかけられる）を CABLE Input（VB-CABLE）に入れて確かめた。

- FxProperties を書き換えたあとは、Audiosrv を再起動するだけで APO が読み込まれる（AudioEndpointBuilder の再起動や PC の再起動は不要）。
- audiodg.exe は APO を COM の集約（aggregation）で作る。集約に対応していないと動かない。
- GFX の枠では `Initialize` に `APOInitSystemEffects`（56 バイト）が渡される。
- 48 kHz、2ch では 1 周期 480 フレーム（10 ms）。入力と出力は同じバッファ（in-place）。
- 入れた直後の最初のストリームだけ、`AUDCLNT_E_DEVICE_INVALIDATED` で失敗することがある。開き直せば動く。
- TestGainDb=-6 のとき、CABLE Input → CABLE Output で -6.00 dB を測定できた。外すと 0.00 dB に戻った。

## APO と本体の受け渡しで確かめたこと（2026-11-03）

APO を CABLE Input に入れ、素通しのときは -3 dB、HostSim は -12 dB をかける設定で測った。

- audiodg.exe（LOCAL SERVICE）から `Global\` に共有メモリとイベントを作れ、一般ユーザーの HostSim から開けた。高精度タイマーも使えた。
- HostSim を通すと -12.00 dB。受け渡しの往復は平均 23 µs、最大 162 µs（上限 6000 µs）、時間切れ 0。
- 遅延（ApoProbe --latency、VB-CABLE 内部の遅延を含む）: APO なし 58.4〜59.1 ms、APO のみ 58.8〜60.1 ms、HostSim で処理 58.1〜58.9 ms。差はなく、遅延は増えていない（同じ周期のうちに結果を返している）。
- HostSim の処理に 8 ms かかる（上限 6 ms を超える）と、全周期が時間切れになり素通し（-3 dB）で流れ続けた。
- HostSim を強制終了すると、心拍の上限 0.5 秒ぶん（50 周期）は時間切れで素通し、その後は待たずに素通しになった。
- HostSim は APO が共有メモリを作ってから 0.5 秒以内につながる。それまでの周期は素通し。

## 本体アプリ

`build\PRISystemRack_artefacts\<構成>\PRISystemRack.exe`

- 上の「再生デバイス」で APO の入ったデバイス（`[APO]` 付き）を選ぶと、APO とつながって処理を始める。

- 描画は普段は Direct2D（文字を DirectWrite で描くので、ソフトウェア描画より文字がくっきりする）。JUCE 8.0.16 の Direct2D には、ネイティブの枠をマウスでドラッグしてサイズを変えると中身がタイトルバーの高さ分上にずれる不具合があるので、`WindowRendering` がウィンドウをサブクラス化して、ドラッグの間（`WM_SIZING` から `WM_EXITSIZEMOVE` まで）だけソフトウェア描画に切り替える。ドラッグが終わって Direct2D に戻しただけではずれたままになるので、戻した後にプログラムからウィンドウの高さを 1 ピクセル変えて元に戻す（これで正しい位置に描かれる。2026-11-03 にマウス操作の再現で確認）。プラグインの画面のウィンドウはソフトウェア描画のまま。Direct2D の文字はグレースケールのアンチエイリアス（JUCE が固定している）で、ブラウザの ClearType ほどではない。
- ウィンドウは設定を済ませてから 1 回だけ作る（`PluginWindow`・`AppRackWindow` は `DocumentWindow` を addToDesktop = false で作ってから `addToDesktop()`、ダイアログは JUCE の `LaunchOptions::launchAsync` の代わりに `DialogLaunch::launchAsync`）。JUCE はウィンドウを作ったあとに `setUsingNativeTitleBar` や `setResizable` を呼ぶとウィンドウを作り直し（`TopLevelWindow::recreateDesktopWindow`）、そのたびにまだ見えないウィンドウを `toFront (true)` でアクティブにするので、プラグインの画面や「プラグインを追加」を開くまでにメイン画面のタイトルバーが何度も「手前 / 手前でない」の色に変わっていた（2026-11-12、手前のウィンドウの移り変わりを WinEvent で記録して確認。1 つの画面で 3 回作っていた。プラグインの画面も作り直したウィンドウに付け直されていた）。JUCE の `setVisible` はアクティブにしない（`SW_SHOWNA`）ので、作り直しをなくすと開いた画面のタイトルバーが手前でない色のままになる。表示したあとに `toFront (true)` で 1 回だけアクティブにする（以前は最後の作り直しの `toFront` で、結果としてアクティブになっていた）。
- ボタンと選択欄の高さは 24 px、ボタンの幅は文字の長さ ＋ 左右 8 px（`Theme::controlHeight` / `Theme::buttonWidth`）。配色と文字の大きさは `Source/App/Theme.h` にまとめてある。
- 入力・出力の欄は 2 段: 上は小さな文字のラベルの行（スライダーの上に「ゲイン」とその右に説明（アプリ用ラックだけ）、メーターの真上に種類の名前、右端に最終的なレイテンシー（出力の欄だけ））、下はゲインの行（左端に「入力」「出力」（合流）の札、スライダー、メーターと右の数値）。メーターの目盛りの数値はその下に出す。
- 入力・出力のゲインのスライダーは、マウスホイール 1 目盛りで 0.5 dB ずつ動く（0.5 dB の倍数にそろえる。ドラッグは 0.1 dB 刻み、ダブルクリックで 0 dB）。スライダーのつまみが動く部分とレベルメーターは同じくらいの幅に分ける（つまみの部分は倍率をかける前で 110〜300 px）。メーターが 40 px より狭くなるときはメーターを出さない（右のピークの数値は出す）。メーターは枠の中に左（上）と右（下）の 2 本のバー（1 チャンネルなら左右とも同じ、3 チャンネル目以降は左右の両方に入れる）。目盛りはバーの中の線と下の数値（数値は右から並べ、詰まるものは省く）。右に数値（左右の大きい方）。見出しの行の、メーターの真上にメーターの種類の名前を出す（出力の欄では最終的なレイテンシーの手前まで）。
  - **メーターの種類**（メーターか種類の名前の上のマウスホイールで順に、右クリックで一覧から選ぶ。入力・出力の欄のすべて（メインのラックとアプリ用ラック）で共通で、どこで変えてもほかの欄も同じ種類になる。設定の `sectionMeter`、既定はピーク＋RMS）: ピーク（-60〜0 dB。落ちるのは 40 dB/秒）、RMS（300 ms の平均）、ピーク＋RMS（RMS のバーの後ろにピークを薄く重ねる）、VU（300 ms の平均に 3 dB 足してサイン波で読む（AES17）。-18 dBFS = 0 VU、-20〜+3 VU）、ラウドネス（ITU-R BS.1770 の K 特性。モーメンタリー 400 ms、ショートターム 3 秒、インテグレーテッド（-70 LUFS と -10 LU のゲート。画面を開いてからの分。メーターの左クリックか右クリックのメニューでリセット。入力と出力の欄はいっしょにリセットする）。左右を合わせた 1 本のバー）、K-System の K-20 / K-14 / K-12（RMS（AES17）の 0 を -20 / -14 / -12 dBFS に置く。0 から黄色、+4 から赤。ピークを薄く重ねる）、表示しない（枠・数値・種類の名前を出さないが場所は残し、その場所のホイール・右クリックで戻せる）。表示メニューの「入出力のメーター」からも選べる。
  - 値はオーディオのスレッドで集める（`LevelMeterTap`: サンプルのピーク、2 乗の和、K 特性をかけた 2 乗の和。NaN・無限大は 0 として数え、メーターが固まらないようにする）。画面（`SectionMeter`）がタイマーのたびに読み、時間窓の平均やゲートを計算する。どの種類の値も毎回計算するので、切り替えるとすぐその表示になる。
  - ピークホールド（表示メニューの「入出力のメーター」の中と、メーターの右クリックのメニューで切り替える。既定は ON。設定の `peakHold`）は表示しているバー（ピークを重ねる種類はピーク）の最大の位置に縦線を出し、1.5 秒保ってから 20 dB/秒で下げる。
- プラグインを作っている途中は、別のプラグインを作り始めない（`PluginChain::createInstance`。どのラックでも共通）。UJAM の UFX-REVERB は初期化の中で自分でメッセージを回すため、その間にプラグインの選択画面の「読み込む」の遅延呼び出し（`juce::Timer::callAfterDelay` はタイマーを止める前に呼ぶ）が何度も発火し、同じプラグインを入れ子で作り続けてスレッド 500 本以上・メモリ 7 GB を使い、PC 全体が止まった（2026-11-06）。選択画面では、遅延呼び出しの中で読み込まず、1 回きりのメッセージ（`callAsync`）を送るだけにした（遅延呼び出しの中で「2 回目は何もしない」としたら、内側で消えたタイマーを外側でもう一度消してヒープが壊れ、0xC0000374 で落ちた）。ヒープの破損は `CrashLog` が起きた瞬間に記録する（プラグインを守る `__except` に受け止められると何も残らないため）。
- 1 つのラック（メインのラック・各アプリ用ラック）に入れられるプラグインは 50 個まで（`PluginChain::maxPlugins`）。上限なら「＋ プラグインを追加」と ⋯ メニューの「複製」を押せず、ファイルのドロップなどで足そうとしても足さずに理由を出す。
- 各プラグインの行にそのプラグインのレイテンシー（ms とサンプル数）、出力の欄に最終的なレイテンシー（ON のプラグインの合計。アプリ用ラックは取り込みの遅れも足す）を出す。Windows やデバイスのバッファーの遅れは含まない。
- 「音声テスト ☐入力 ☐出力」のチェックボックス（メイン画面の上の欄のバッファの行の右。アプリ用ラックのウィンドウにはない。`TestToneToggles`）で、440 Hz のサイン波（-20 dBFS、全チャンネル同じ音）を鳴らす（チェックを外すと止める。入り・切りは 20 ms でなめらかに変える。`TestTone`）。「入力」は入力ゲインの手前に足すのでプラグインを通った音を、「出力」はプラグインのあと・出力ゲインの手前に足すのでプラグインを通らない音を確かめられる。ほかに何も鳴っていなくても APO が動くよう、鳴らす間は無音を流す（アプリ用ラックがあればもともと流している）。保存はせず、画面を作り直したときは止める。再生デバイスで「有効」でないときは押せない。
- 言語は英語（既定）と日本語。表示メニューで切り替えると、その場で画面を作り直す（開いているプラグイン画面は閉じる）。設定の `language`（`en` / `ja`）に保存する。フォントは英語なら Segoe UI、日本語なら Meiryo UI。

### アプリ用ラック

指定したアプリ（exe）の音だけを WASAPI Process Loopback で取り込み、専用のプラグインで処理して、メインのラックの出力の手前（メインのプラグインのあと、出力ゲインより前）に合流させる（合流先は固定。以前あった「入力の前」は使い道がないので外した。古い設定・プリセットの `merge` は読まない）。メイン画面では、「＋ プラグインを追加」の左（出力の欄の見出しの位置から）にアプリ用ラックの名前の札を並べ、入りきらなくなったらボタンの右に左詰めで続け、それぞれの札から出力の欄へ矢印でつなぐ（右にも入りきらない分は出さない。バイパス中のラックの札は枠をバイパスの色に、名前を暗くする）。アプリ用ラックは 10 個まで（`RackEngine::maxAppRacks`。上限なら「＋ ラックを追加」を押せない）。

使わない人が多い機能なので、設定メニューの「アプリ用ラックを使う」で切り替える（既定は無効。設定の `appRacks`。この設定がなかった版から上げたときは、前回の構成にアプリ用ラックがあれば有効で始める）。無効の間は、上の欄の「アプリ用ラック」の行を出さず（上の欄が 1 行分低くなる）、ラックは作らない（音の取り込みもプラグインの読み込みもしない）。構成やプリセットにあるアプリ用ラックは、中身をそのまま預かって保存のときに書き戻す（`RackEngine::heldAppRacks`。上書き保存・新しいプリセットとして保存でもラックは消えない。「新規作成」では空になる）。ラックがある状態で無効にすると、ラックを止めて中身を預かり（削除はしない）、その旨を知らせる。有効に戻すと預かった中身からラックを作り、プラグインを 1 つずつ読み込む。切り替えただけでは「変更あり」にしない。

- メイン画面の「＋ ラックを追加」で増やす（いくつでも）。上の欄の札（ラックの名前）をダブルクリックすると、そのラックのウィンドウを開く。ウィンドウを閉じても隠れるだけで、ラックは動き続ける。札を右クリックすると「削除」のメニューが出る（ラックの画面の [ラックを削除] と同じ確認あり）。「＋ ラックを追加」は左クリックのときだけ働く。札の左の丸は状態（緑: 取り込み中、灰: 対象アプリが起動していない、オレンジ: 取り込みの失敗か二重に聞こえる）で、丸をクリックするとそのラックのバイパス（ラックの画面の [バイパス] と同じ）を切り替える。バイパス中は丸の代わりに迂回の矢印（バイパスの色）を出し、札の枠もバイパスの色にする。札と「＋ ラックを追加」は上の欄のほかの部品より一回り小さく（高さ 20、文字 12）、1 行に入りきらなければ次の行へ折り返す（上の欄の高さは行の数に合わせて伸びる）。
- 「アプリを選ぶ...」で対象アプリを選ぶ（音声を出しているプロセスの一覧から選択。起動していないアプリも名前で登録できる）。アプリが起動するまで待ち、起動し直したらつなぎ直す。同じ exe の根元のプロセスごとに取り込み、子プロセスはツリーごと取り込まれる。
- 取り込みの準備（Process Loopback の有効化。最大 5 秒）は取り込みスレッドで行い、画面は待たない。準備や取り込みに失敗したプロセスは、ラックの画面に理由を出して、5 秒あけてから試し直す。Windows Audio が再起動すると（再生デバイスの［有効］・［無効］の切り替えなど）、それより前に始めた Process Loopback の取り込みは、エラーを返さず、届き続けるパケットの中身が 0 になるだけになる（対象アプリが黙っているときと見分けられない）。そのため 1 秒ごとのプロセスの確認で Windows Audio のサービス（Audiosrv）と音声エンジン（audiodg.exe）の PID を調べ（管理者は要らない）、どちらかが変わったらすべての取り込みを作り直す（止まっている間は作らない。`GetAudioServiceState`）。audiodg.exe も見るのは、メモリーの少ない PC では Audiosrv がほかのサービスと同じ svchost で動き、再起動しても PID が変わらないことがあるため（audiodg.exe は音を出していない間はいないことがあるので、いないときは比べない）。サービスの状態を調べられなかったとき（一時的な失敗）は「止まった」と見なさず、何もしない。2026-11-13 に、切り替えのあと Gather の音が「取り込み中」のまま無音になっていたのを、新しく取り込むと音が来ることで確認して追加（最初はパケットが来なくなると考えて、来ない時間で見張ったが、パケットは届き続けていて効かなかった）。
- **元の音を消す方法**: 対象アプリの出力先を、聞こえないデバイス（CABLE Input など）に変える（Gather などはアプリの設定で選ぶ）。Process Loopback はアプリの音量・ミュートをかけたあとの音を取り込むので、ミュートでは消せない（LoopbackMuteTest で確認）。ラックの画面に、対象アプリがいまどのデバイスに出しているかを出し、メインのデバイスに出していたら「二重に聞こえる」と警告する（メイン画面の札の丸もオレンジになる）。出力先は、セッションが動いているだけでなく、音量メーターで実際に音が出ている（-70 dB を超えた）デバイスだけを数え、最後に音が出てから 10 秒は覚えておく。Gather は既定のデバイスに無音のままセッションを開いて動かし続けるので、動いているかだけで見ると、出力先を別のデバイスにしていても「二重に聞こえる」と誤って警告していた（2026-11-05 に確認）。
- 取り込んだ音は FIFO（2 周期ぶん）を通してメインの処理の中で合流する。対象アプリのデバイスとメインのデバイスの時計のずれは、FIFO の量が一定になるよう読み出しの速さを ±0.5% 以内で変えて吸収する。メインの経路の遅延は増えない。
- アプリ用ラックがあるときは、ほかに何も鳴っていなくても APO が動くよう、本体がメインのデバイスに無音を流し続ける。
- 起動オプション `--open-app-racks` で、起動時にすべてのアプリ用ラックのウィンドウを開く（確認用）。

確かめたこと（2026-11-03、メイン = CABLE Input、対象 = ApoProbe.exe）:

- ApoProbe が DELL S2722DC（HDMI）に流した -40 dBFS のサイン波が、ラックを通って CABLE Output に -0.09 dB で届いた。ラックの画面は「取り込み中: ApoProbe.exe（プロセス 1 個）｜合流までの遅れ 約 30 ms」「出力先: → DELL S2722DC（元の音は聞こえません）」。
- ApoProbe の出力先をメインのデバイス（CABLE Input）にすると、二重に聞こえる警告が出た（このとき 1 kHz は元の音と重なって -5.7 dB になった）。

### 画面の文字列を足すとき

- ソースには英語で書き、`TRANS ("...")` で囲む。`TRANS` に渡す文字列は ASCII だけにする（`µ` などは `%us%` のような目印にして、あとから `replace` で差し込む）。
- 値を差し込む場所は `%name%` のように書いて `replace` で置き換える。パス（`\` を含む）は訳の中に書かず、目印で差し込む（訳ファイルは `\\` を解釈しないため）。
- 日本語の訳を `Resources/Translations/ja.txt` に `"English" = "日本語"` の形で足す（アプリに組み込まれる）。
- 補助プログラム（PRISystemRackSetup.exe）のログは英語のみ。開発用の PowerShell スクリプトは日本語のまま。
- 再生デバイスの右に切り替え [ 有効 | 無効 ]（`EnableSwitch`）。2 つに分かれたボタンで、今の状態の側を色付き・太字にして状態の表示を兼ね（有効なら青、無効なら灰）、反対側を押すと切り替える。押せる側の文字の左に盾のマークを付ける（Windows の決まりどおり、管理者の許可が要る操作に盾を付ける）。ツールチップは、今の状態の側では状態の説明、押せる側では押すと何が起きるか。選んだデバイスに APO を入れる・外す（UAC が出て、Windows Audio を再起動する）。アプリ側の確認は出さない（UAC の確認がその役目で、そこで取りやめれば何も変わらない）。ただし、UAC の確認が出ないとき（すでに管理者として動いている、UAC が切られている、管理者のアカウントで UAC が「通知しない」＝ `ConsentPromptBehaviorAdmin = 0`）は、押しただけで音が止まらないようアプリ側で確認を出す（`WillShowUacPrompt`）。切り替えのあとデバイスの一覧を読み直して実際の状態を映し、結果（有効にした・無効にして何に戻した・取りやめた）をステータスバーに 10 秒出す。切り替え中はボタンを押せず、ステータスバーに「切り替え中...」。状態とボタンの幅は長い方の文言に合わせて固定する。Equalizer APO が入っていれば控えてから外し、無効にすると元に戻す。画面（デバイスの一覧、ツールチップ、確認、ステータスバー）には特定の製品の名前を出さず、レジストリから分かる APO の名前は使わずに「他の APO」「APO なし」とだけ出す。有効でないときは APO から処理の依頼が来ないので、バイパスは押せなくし、メインのラックとアプリ用ラックの ON のプラグインをすべて「Resting」（日本語では「休止」）と表示する（`PluginChain::setDeviceEnabled`）。APO の DLL は先にインストールしておく（開発中は `dev-install.ps1 -Endpoint ''`）。
  - 控えて外す枠（LFX, GFX, UI, SFX, MFX, EFX, Composite SFX/MFX/EFX）と設定画面に出る名前は `Source/Common/FxSlots.h` にまとめてあり、本体アプリの「ほかの APO があるか」の判定も同じ一覧を使う。
  - FxProperties がまだないデバイス: 再生デバイスのキー（`MMDevices\Audio\Render\{GUID}`）は、Windows の初期の権限のままだと管理者でも値は書けるが下にキーを作れない（Administrators は SetValue と ReadKey だけ）。AG06 で初めて使ったサンプルレート（96 kHz）のエンドポイントがこれで、［有効］が `cannot create FxProperties (5)` で失敗していた（2026-11-11。44.1 / 48 kHz 用は、以前 Equalizer APO が権限を Administrators のフルコントロールに書き換えていたので作れた）。そのため Setup ツールは起動時に SeRestorePrivilege と SeBackupPrivilege を有効にし、作れなかったときだけ `REG_OPTION_BACKUP_RESTORE` で作る（権限は書き換えない。作ったキーは親の継承する権限を受け継ぎ、Windows が作る Properties キーと同じ権限になる）。外すときや取り消すときに、作った空のキーを権限で消せなければ、同じ特権で開いて消す（NtDeleteKey）。
  - 入れるとき: 控えのキーを作る前に FxProperties を書き込めるか確かめる。途中で失敗したら、外した値を書き戻して控えのキーを消す（中身の欠けた控えを残さない。残ると次に入れるとき今の登録を控えずに上書きしてしまうため）。
  - 外すとき: 入れたあとで別の APO が入れ直されていて、控えと違う値が入っている枠は、今の値を残して控えの値は書き戻さない（書き戻さなかった値は setup.log に残す）。控えのキーは消す。
  - 外すときの確認文の「元の状態」は、控えのキーにある名前を出す。
  - Windows Audio が 15 秒で止まらなかったときは、起動し直しは試みるが、変更がまだ反映されていないので失敗（終了コード 1）を返す。

確かめたこと（2026-11-03、CABLE Input、入力 → SPAN → 出力、出力ゲイン -12 dB）:

- ApoProbe で -12.00 dB。アプリを閉じると 0 dB（素通し）に戻る。再起動すると保存した構成で -12 dB に戻る。
- 1 kHz → 5 kHz と流すと、SPAN のアナライザーがリアルタイムに追従した（Equalizer APO では動かなかった点）。
- 受け渡しの往復は平均約 80 µs、最大約 900 µs（SPAN の処理を含む）。遅延は APO なしと同じ範囲（VB-CABLE のばらつき 50〜60 ms の中）。
